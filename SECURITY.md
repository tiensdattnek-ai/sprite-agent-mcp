# Security Policy

## Supported versions

| Version | Supported |
|---|---|
| 1.x | ✅ |
| < 1.0 | ❌ |

## Threat model (important for MCP hosts)

This server **never executes code supplied by a tool call**, spawns child processes, evaluates expressions, fetches URLs, or reads arbitrary repository files. It only writes art assets into one output root.

- **Write guard**: `src/core/paths.ts` rejects `..`, absolute paths, hidden directories, protected directories (`src`, `scripts`, `tests`, `.github`, `dist`, `node_modules`, …), protected filenames and all source-code extensions. The cap is 32 MB per file.
- **Integrity**: `integrity/manifest.json` lets any client verify the shipped source (`sprite_verify_integrity`). If it reports `clean:false`, do not continue and restore from git.
- **stdio hygiene**: logs go to stderr; stdout is pure JSON-RPC.
- **HTTP**: set `SPRITE_HTTP_TOKEN` for a bearer token, `SPRITE_STRICT_HOSTS=1` plus `SPRITE_ALLOWED_HOSTS` for DNS-rebinding/origin protection when exposing beyond localhost. CORS is permissive by default for local development and preview environments.
- **No secrets**: no credentials, no environment dumping, no telemetry, no network calls.

## Reporting a vulnerability

Please **do not open a public issue**. Open a private security advisory on the GitHub repository ("Report a vulnerability") or contact the maintainers through the repository's security contact. Include reproduction steps, impact and a suggested fix. We aim to acknowledge within 5 business days.

Please do not attach patches generated by an agent that edited the repository — see [POLICY.md](POLICY.md).
